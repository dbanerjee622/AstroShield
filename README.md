# 🚀AstroShield — Debris Field Simulator🚀

A sensor simulator seen from a rocket: debris flies through a field bent by
the gravity of nearby planets, and you write the code that predicts each
piece's trajectory from the sensor readings. 

## Our Inspiration :

As space exploration continues to grow, one of the most escalating threats is posed by space debris and the potential danger it has on future space missions. This inspired us to create a system called AstroShield, which could detect incoming debris and actively prevent collisions with a spacecraft.

## What It Does : 

AstroShield utilizes real-time space debris tracking data generated by a realistic simulation to analyze the trajectory of the orbital debris. When a potential collision is detected, the system deploys a kinetic impactor projectile (tungsten ball) to alter the debris trajectory and reduce the risk of collision with the spacecraft.

## How We Built It : 

We started by building the base of the simulation for AstroShield using Claude to help us write the code. This allowed us to get realistic data from the simulation that we could use to calculate a formula for the general trajectory of space debris. We then created an alternate equation that calculated when to deploy the kinetic impactor projectile, which for us was a tungsten ball, so that it could intercept the orbital debris threatening to collide with the spacecraft. Afterwards, we coded the equations and sensors that we used to detect the space debris into VSCode using Python. By attaching the VSCode document to the simulation, we created a working model of AstroShield, which allows the spacecraft to shoot tungsten balls at space debris that pose a collisional threat.

## Challenges We Ran Into :

One of the major challenges we encountered during the process of designing AstroShield was finding a reliable way to predict the trajectory of the debris that could collide with the rocket. There are thousands upon thousands of floating space debris which pose a massive threat in the atmosphere, and trying to calculate the trajectory of each one would be near impossible. To solve this, we found a general equation which represents the trajectory of all space debris through fillable variables : 

a(deb_r,t) = Σᵢ((G·M·(π(t)-deb_r))/(|π(t)-deb_r|³).

## Accomplishments That We're Proud Of :

For most of our team, this was our first hackathon, so developing a fully functional project from the ground up was a huge accomplishment. We're proud of building AstroShield into a working simulation that connects orbital physics, trajectory prediction, and collision interception. One of our biggest accomplishments was translating gravitational equations into Python code that analyzes debris movement and predicts potential collisions. We also developed a system to calculate when a tungsten-ball impactor should be deployed to redirect threatening debris. Bringing these components together allowed us to demonstrate how spacecraft could use real-time tracking and predictive calculations to respond to potential collisions.

## What We Learned : 

Through AstroShield, we learned how to use physics and programming together to model the movement of space debris. We learned how to apply gravitational equations in Python to predict debris trajectories and determine whether an object could collide with a spacecraft. We also explored how to calculate the timing and trajectory needed for a kinetic impactor to intercept dangerous debris. Combining our mathematical models with a live simulation taught us how to turn theoretical calculations into a practical collision-prevention system. 


## What's Next For AstroShield :

Our next goal for AstroShield is to develop a tangible 3D model that brings our simulation into the physical world. We plan to integrate a radar system, a camera, and motion-detection sensors to identify moving objects and determine whether their projected trajectories pose a collision risk. Using our existing Python code, the device would analyze incoming objects and alert the user (or a simulated spacecraft) when a potential collision is detected. These alerts would include changing LED colors to indicate different threat levels and producing an audible warning. Ultimately, we hope to combine our simulation, sensors, and physical hardware into a prototype that demonstrates how real-time debris tracking and collision prediction could help protect spacecraft from potential impacts.


# Run it

Install the Python dependency once:

```sh
python3 -m pip install -r requirements.txt
```

Start the Python API in one terminal:

```sh
python3 src/api.py
```

Start the browser app in a second terminal:

```sh
npm install
npm run dev      # http://localhost:5173; /api requests are proxied to Python
npm run build    # production build in dist/
```

## Where things live

```
src/
  trajectory.py     Python interception solver
  api.py            HTTP endpoint that calls the solver
  config.js         default settings (the sliders edit these live)
  state.js          shared UI state (paused, selection, visibility toggles)
  main.js           wires everything together and runs the frame loop
  sim/              physics + sensor, no drawing
    simulator.js    debris spawning, stepping, sensor scans ("INTERCEPTOR" hooks)
    bodies.js       sun/planet definitions, orbits, gravity
    math.js         rounding and seeded RNG
  render/           three.js scene
    stage.js        renderer, camera, controls, sky, lights
    rocket.js  planets.js  debris.js  overlays.js  textures.js
  ui/               DOM panels
    hud.js          top bar, sensor feed, detail panel, planet tables
    controls.js     sliders, toggles, buttons, click-to-select
    notify.js       toasts and impact flash
    format.js       number/unit formatting
  styles/           base (tokens), layout, panels, view
```

`window.sim` and `window.CONFIG` are exposed for poking around in the browser console.
